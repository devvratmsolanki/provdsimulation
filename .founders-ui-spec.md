# VISUAL + INTERACTION SPEC — Founder's Office (`/founders-office`)

Companion to `.founders-spec.md`. That document owns *what happens*. This one owns *what it looks like and how it feels under the hand*. Where the two disagree, `.founders-spec.md` wins and I want to hear about it.

**Budget check up front:**
- New design tokens: **0**
- New keyframes: **0** — every motion beat in all eight stages is served by `.stage-enter`, `.reveal-down`, `.toast-in`, `.blink`, `.pulse`, `.flash-error` or a plain Tailwind `transition-*`. See §Motion Doctrine for what I used instead of the keyframes I was tempted by.

## 0. THE HOUSE STYLE (read once, apply eight times)

Everything below is already in the codebase. Learn these six blocks and you can build all eight stages without inventing anything.

### 0.1 Stage header — duplicate verbatim, change three strings

```tsx
<section className="stage-enter">
  <div className="mb-6">
    <div className="flex items-start justify-between gap-4">
      <div className="eyebrow mb-4">
        <Mic className="size-3.5" />
        Stage 1 — Intake
      </div>
      <span className="hidden shrink-0 font-mono text-[11px] tracking-[0.08em] text-muted-ink sm:block">
        STAGE 1 / 8
      </span>
    </div>
    <h1 className="text-3xl font-extrabold tracking-tight text-text-warm">
      Nine Sentences, Three Actual Asks
    </h1>
    <p className="mt-3 max-w-2xl text-[15px] leading-relaxed text-muted-ink">
      {/* one-sentence task framing */}
    </p>
  </div>
  {/* stage body */}
</section>
```

The `STAGE n / 8` counter is the arc device (§6). It is derived data, not new copy. It repeats in the sidebar and in the mobile brand row.

### 0.2 Panel scale — exactly two levels, no third

| Level | Classes | Used for |
|---|---|---|
| Outer panel | `rounded-[var(--radius-md)] border border-border-dark bg-carbon p-5 sm:p-6` | the stage's working surface |
| Inner tile / row | `rounded-[var(--radius-sm)] border border-border-dark bg-surface p-3.5` | a single item inside a panel |

Long lists do **not** get 12 bordered cards. They get one outer panel with `divide-y divide-border-dark` rows. That is the whole density trick.

### 0.3 The gilt intensity ramp — the most important rule in this document

Gilt encodes **how much attention/commitment this carries**, never *whether you were right*.

| Weight | Classes | Meaning |
|---|---|---|
| Strong | `border-gilt bg-gilt text-void` | full commitment (ASK, DO NOW, ADD EVIDENCE, selected fact) |
| Medium | `border-gilt/50 bg-gilt/[0.12] text-gilt` | partial commitment (CONTEXT, DELEGATE, SOFTEN) |
| Quiet | `border-border-dark bg-surface text-text-warm` | acknowledged, minimal spend (DEFER, KEEP) |
| Discard | `border-border-dark bg-transparent text-muted-ink` + row at `opacity-50` | NOISE, DECLINE, CUT |

`pass` and `error` are **verdict colors only**. They may fire in exactly four places across the whole track:
1. Stage 2 — the minute budget going negative (rejection).
2. Stage 5 — the 18.0-month board floor.
3. Stage 7 — a question Ansel will actually ask.
4. Stage 8 — the eight-minute budget going negative.

No stage tells the operator their judgment was correct. That is the product. If you catch yourself painting a fact card `border-pass`, you have broken the simulation.

### 0.4 Selectable option card — Stages 3C, 4, 6

```tsx
<button
  type="button"
  aria-pressed={selected}
  onClick={...}
  className={`flex w-full items-start gap-3 rounded-[var(--radius-md)] border p-4 text-left
    text-[13px] leading-snug transition-colors ${
    selected
      ? 'border-gilt bg-gilt/[0.08] text-text-warm'
      : 'border-border-dark bg-surface text-text-warm hover:border-gilt'
  } ${dimmed ? 'opacity-45' : ''}`}
>
  {selected && <Check className="mt-0.5 size-4 shrink-0 text-gilt" />}
  <span>{label}</span>
</button>
```
`:focus-visible` is already handled globally (2px gilt outline, 2px offset). Never add a focus class.

### 0.5 Primary CTA — one per stage, bottom-left

```tsx
<button type="button" onClick={...} disabled={!ready}
  className="reveal-down mt-6 inline-flex w-full items-center justify-center gap-3
    rounded-[var(--radius-md)] bg-gilt px-6 py-3.5 text-sm font-bold tracking-[0.02em]
    text-void transition-colors hover:bg-gilt-dim
    disabled:cursor-not-allowed disabled:opacity-40 sm:w-auto">
  Proceed to Stage 2 — Attention Triage
  <ArrowRight className="size-4" />
</button>
```
Mount it only when the stage is satisfiable, so `.reveal-down` reads as *unlocking*. **Two exceptions:** Stages 5 and 8 have no solved state — their CTAs are present from first paint and carry **no** `.reveal-down`. That absence is the signal that there is no right answer here.

### 0.6 Caps vs. bounds — never mix these

- **Hard bound** (a stepper at 0 or its max): `disabled` the control. The system says "this does not exist."
- **Judgment cap** (240 minutes, 3 facts, 3 written items, 8 minutes): control stays **enabled**. Clicking fires an error toast + `.flash-error` on the row. The system says "you can want this; you cannot have it." That rejection *is* the lesson. Disabling it steals the lesson.

### 0.7 Shell

`components/founders/founders-simulation.tsx` mirrors `simulation.tsx` exactly, with three changes:
- `Sidebar` gets `steps` (9 rows: the 8 stages + Talent Report), `subtitle="Founder's Office"`, `duration="Est. duration: 13–16 minutes"`.
- `ContextBar` gets `track="Simulation Preview — Founder's Office Track"` and its note string.
- Main column widens: `mx-auto w-full max-w-5xl flex-1 px-5 py-8 sm:px-10`. `max-w-4xl` cannot hold a `1fr / 420px` split at `lg`. This is a value in a new file, not a token.
- Mobile brand row (`md:hidden`) gains the arc counter:
  ```tsx
  <p className="ml-auto font-mono text-[11px] text-muted-ink">STAGE {stage} / 8</p>
  ```

## STAGE 1 — The Voice Memo

### Layout
```
Desktop & 375px: single column, everything inside main's max-w-5xl.
  header block
  operator name row          (flex flex-wrap items-center gap-3)
  player card                (outer panel)
  transcript panel           (outer panel, divide-y rows)
  CTA
```
No grid. Stage 1 is the calmest screen in the track — it has to be, because Stage 2 is not.

### Visual hierarchy
1. `h1` — the title is the instruction.
2. The **player card's gilt scrubber knob** — the one bright object on screen, telling you a human is talking.
3. The transcript block as a grey mass — deliberately hard to parse at a glance. That is the point: nine sentences, three asks.
4. The chips, which only resolve into a rhythm as you work.

### Signature element — the transcript rows

Player card first:
```tsx
<div className="rounded-[var(--radius-md)] border border-border-dark bg-carbon">
  <div className="flex items-center gap-3 border-b border-border-dark px-5 py-3">
    <Mic className="size-4 text-gilt" />
    <div>
      <p className="text-[13px] font-semibold text-text-warm">Priya Raghavan</p>
      <p className="text-[11px] text-muted-ink">Voice memo · 07:58</p>
    </div>
    <p className="ml-auto font-mono text-[11px] tabular-nums text-muted-ink">0:00 / 1:34</p>
  </div>
  {/* decorative scrubber — NOT an input, NOT focusable */}
  <div aria-hidden="true" className="px-5 py-4">
    <div className="relative h-[2px] w-full bg-border-dark">
      <span className="absolute left-0 top-1/2 size-4 -translate-y-1/2 rounded-[var(--radius-sm)]
                       border-2 border-void bg-gilt" />
    </div>
  </div>
</div>
```
It is fake. Give it `aria-hidden="true"`, no `tabindex`, `cursor-default`. Do not build a fake control a keyboard user can land on and fail to operate — that is worse than no control.

Transcript panel, nine rows:
```tsx
<div className="mt-4 rounded-[var(--radius-md)] border border-border-dark bg-carbon">
  <div className="flex items-center justify-between border-b border-border-dark px-5 py-3">
    <p className="text-[10px] font-bold uppercase tracking-[0.14em] text-muted-ink">
      Transcript — auto-generated
    </p>
    <p className="font-mono text-[11px] tabular-nums text-muted-ink">{tagged} / 9 TAGGED</p>
  </div>

  <div className="divide-y divide-border-dark">
    {LINES.map((l, i) => {
      const tag = tags[l.id]                       // 'ASK' | 'CONTEXT' | 'NOISE' | undefined
      return (
        <div key={l.id}
          className={`grid grid-cols-1 gap-2.5 px-5 py-4
                      sm:grid-cols-[28px_1fr_auto] sm:items-start sm:gap-4
                      ${tag === 'NOISE' ? 'opacity-50' : ''}`}>
          <span className="font-mono text-[11px] leading-6 text-muted-ink">{`L${i + 1}`}</span>
          <p className={`font-mono text-[13px] leading-relaxed transition-colors
                        ${tag ? 'text-text-warm' : 'text-muted-ink'}`}>
            {l.text}
          </p>
          <div role="group" aria-label={`Classify line ${i + 1}`}
               className="flex gap-1.5 sm:justify-end">
            {(['ASK','CONTEXT','NOISE'] as const).map((t) => (
              <button key={t} type="button" aria-pressed={tag === t}
                onClick={() => setTag(l.id, t)}
                className={`min-h-11 rounded-[var(--radius-sm)] border px-2.5
                            text-[10px] font-bold uppercase tracking-[0.1em]
                            transition-colors sm:min-h-0 sm:py-1.5 ${chipClass(t, tag === t)}`}>
                {t}
              </button>
            ))}
          </div>
        </div>
      )
    })}
  </div>
</div>
```

`chipClass` returns the §0.3 ramp — and this is the whole idea of the stage. The three chips are not three equal buckets; they are **three levels of the same accent**, so a completed transcript is legible as a *signal-strength map* at a glance:

| Tag | Selected classes |
|---|---|
| `ASK` | `border-gilt bg-gilt text-void` |
| `CONTEXT` | `border-gilt/50 bg-gilt/[0.12] text-gilt` |
| `NOISE` | `border-border-dark bg-transparent text-muted-ink` (+ row `opacity-50`) |

Unselected, any chip: `border-border-dark bg-surface text-muted-ink hover:border-gilt hover:text-text-warm`.

An operator who tagged everything ASK sees nine gold bars and feels it before anyone tells them. No correctness reveal needed.

### State styling
- **Default row:** text `text-muted-ink`. It reads as unheard.
- **Hover chip:** border to gilt, text to warm. Row does not change.
- **Focus-visible:** global gilt outline. Chip groups are in DOM order, so `Tab` walks L1→L9 naturally.
- **Selected:** table above. Re-clicking a *different* chip re-tags (increments `intakeRetags`); re-clicking the *same* chip is a no-op — do not implement deselect. Nine rows must all be tagged and an un-tag would be a trap.
- **Disabled:** none in this stage.
- **Error:** none. There is no wrong answer visible here.
- **Committed/locked:** on CTA press the stage unmounts (orchestrator `goTo`). No lock styling needed. If the operator back-navigates via the sidebar, tags persist and remain editable — every retag still counts.

### Motion
- Section: `.stage-enter`.
- CTA: `.reveal-down` at 9/9.
- Row text color: `transition-colors` (~150ms default) on tag. Nothing else moves.

### Mobile (375px)
Grid collapses to one column: line number and text stack, chips wrap to their own row beneath at `min-h-11` (44px). Three chips at `px-2.5` + `text-[10px]` fit 335px with room. Player card header wraps; the `0:00 / 1:34` stamp drops to the second line via `flex-wrap`.

## STAGE 2 — The Queue

### Layout
```
Desktop:  header
          sticky meter bar   (full width of main column)
          one outer panel, 12 divide-y rows
          CTA
375px:    identical stack; each row becomes 2 stacked blocks
```
Deliberately still one column. Twelve rows with four controls each is already 48 targets — a side panel here would be unreadable.

### Visual hierarchy
1. **The number.** `240` at `text-3xl font-extrabold tabular-nums`, sticky, always in view.
2. The subject lines — `text-[13px] font-semibold text-text-warm`, the only warm-white text in the list.
3. Sender names and costs — `text-[11px] text-muted-ink`, mono for the cost.
4. The disposition controls, which are quiet until chosen.

### Signature element — the sticky depleting meter

```tsx
<div className="sticky top-0 z-20 -mx-5 mb-4 border-b border-border-dark bg-carbon
                px-5 py-3 sm:-mx-10 sm:px-10">
  <div className="flex items-baseline justify-between gap-4">
    <p className="text-[10px] font-bold uppercase tracking-[0.14em] text-muted-ink">
      Minutes Remaining
    </p>
    <p className="font-mono text-[11px] tabular-nums text-muted-ink">
      {disposed} / 12 DISPOSED
    </p>
  </div>
  <p className={`mt-1 text-3xl font-extrabold tabular-nums ${meterTone}`}
     aria-live="polite">
    {remaining}
    <span className="ml-1 text-base font-normal text-muted-ink">/ 240</span>
  </p>
  <div className="mt-2 h-[3px] w-full bg-border-dark">
    <div className={`h-full transition-[width] duration-300 ease-[var(--ease)] ${barTone}`}
         style={{ width: `${(remaining / 240) * 100}%` }} />
  </div>
</div>
```
Tone ramp — the operator should *feel* the budget tighten:

| Remaining | `meterTone` | `barTone` |
|---|---|---|
| > 120 | `text-text-warm` | `bg-gilt-dim` |
| 40–120 | `text-gilt` | `bg-gilt` |
| < 40 | `text-error` | `bg-error` |

The `-mx-5 px-5 sm:-mx-10 sm:px-10` bleeds the bar to the edge of the main column so it reads as chrome, not as another card. Nothing else in the track is sticky-to-edge.

### Signature element — the twelve disposition rows

```tsx
<div className="rounded-[var(--radius-md)] border border-border-dark bg-carbon">
  <div className="divide-y divide-border-dark">
    {ITEMS.map((q) => (
      <div key={q.id}
        className={`px-5 py-3.5 transition-opacity ${flashId === q.id ? 'flash-error' : ''}
                    ${d[q.id] === 'DECLINE' ? 'opacity-50' : ''}`}>
        <div className="grid grid-cols-1 gap-3 sm:grid-cols-[1fr_auto] sm:items-center">
          <div className="min-w-0">
            <p className="text-[11px] uppercase tracking-[0.1em] text-muted-ink">
              {q.from}
              <span className="ml-2 font-mono normal-case tracking-normal">{q.cost} min</span>
            </p>
            <p className={`mt-0.5 text-[13px] font-semibold leading-snug text-text-warm
                          ${d[q.id] === 'DECLINE' ? 'line-through decoration-muted-ink' : ''}`}>
              {q.subject}
            </p>
          </div>
          {/* segmented control */}
          <div role="group" aria-label={`Disposition for ${q.subject}`}
               className="grid grid-cols-2 gap-1.5 sm:flex sm:gap-1.5">
            {DISPOSITIONS.map((k) => (
              <button key={k} type="button" aria-pressed={d[q.id] === k}
                onClick={() => dispose(q, k)}
                className={`min-h-11 rounded-[var(--radius-sm)] border px-2.5
                            text-[10px] font-bold uppercase tracking-[0.08em]
                            transition-colors sm:min-h-0 sm:py-2 ${dispClass(k, d[q.id] === k)}`}>
                {k}
              </button>
            ))}
          </div>
        </div>

        {d[q.id] === 'DELEGATE' && (
          <div className="reveal-down mt-2.5 flex items-center gap-2">
            <label htmlFor={`del-${q.id}`}
                   className="text-[10px] font-bold uppercase tracking-[0.12em] text-muted-ink">
              To
            </label>
            <select id={`del-${q.id}`} value={assignee[q.id] ?? ''}
              onChange={...}
              className="rounded-[var(--radius-sm)] border border-border-dark bg-surface
                         px-2 py-2 text-[12px] text-text-warm">
              <option value="">Select…</option>
              {TARGETS.map((t) => <option key={t} value={t}>{t}</option>)}
            </select>
          </div>
        )}
      </div>
    ))}
  </div>
</div>
```

`dispClass` selected states — again the §0.3 ramp, so the finished queue is a legible attention map:

| Disposition | Selected |
|---|---|
| `DO NOW` | `border-gilt bg-gilt text-void` |
| `DELEGATE` | `border-gilt/50 bg-gilt/[0.12] text-gilt` |
| `DEFER` | `border-border-dark bg-surface text-text-warm` |
| `DECLINE` | `border-border-dark bg-transparent text-muted-ink` + row `opacity-50` + subject `line-through` |

**Do not render the Tier column.** `CRITICAL / HIGH / MEDIUM / LOW` is authoring metadata; painting it on screen turns a judgment test into a colour-matching test. The only per-item hint is the honest one: the minute cost.

### State styling
- **Hover (unselected):** `hover:border-gilt hover:text-text-warm`.
- **Focus-visible:** global outline. Tab order: subject block is not focusable; four buttons per row, then the `<select>` when it appears.
- **Selected:** table above.
- **Rejected (over budget):** the control is **never disabled**. On click: `showToast("You don't have the attention. Something has to give.", 'error')`, set `flashId` for 550ms so the row runs `.flash-error`, and leave the previous disposition intact. Clear with a timeout exactly as `stage-data-hunt.tsx` clears `wrongId`.
- **Delegation overload (>3 to one person):** no error, no block. The `<select>` for that person renders `text-gilt` after the 4th assignment — a whisper, not a warning. Overload is a judgment failure, not a rule violation, and Stage 8 will bill for it.
- **Committed/locked:** dispositions stay editable until the CTA. Changing a disposition refunds the old cost and charges the new one; `queueMinutesSpent` is always `240 - remaining` at commit.

### Motion
- Meter bar `transition-[width] duration-300 ease-[var(--ease)]`. **The digits do not animate** — no count-up. See §Motion Doctrine.
- Delegate `<select>`: `.reveal-down`.
- Rejection: `.flash-error` + `.toast-in`.
- CTA: `.reveal-down` at 12/12.

### Mobile (375px)
Sticky bar keeps full-bleed. Row becomes: text block, then a `grid-cols-2` 2×2 of disposition buttons at `min-h-11` — two rows of two, each ~160px wide, unmistakable under a thumb. Sender + cost sit on one wrapped line. The `<select>` goes full width.

## STAGE 3 — The Evidence Room

### Layout
```
Desktop:  header
          phase rail        (three mono chips, full width)
          [3A] chart panel
          [3B] terminal panel      — mounts when 3A solves
          [3C] fact grid + counter — mounts when 3B has been touched
          CTA
375px:    identical; chart scales by viewBox, tab row scrolls horizontally
```
Stage 3's density is **temporal, not spatial**. Three panels stack down the page and each new one arrives with `.reveal-down`, so the page grows under the operator as they earn it. That growth is the memorable thing.

### Phase rail
```tsx
<div className="mb-4 flex flex-wrap gap-2">
  {[['01','Locate the break'],['02','Read the sources'],['03','Commit three facts']]
    .map(([n, label], i) => (
    <div key={n} className={`flex items-center gap-2 rounded-[var(--radius-sm)] border px-3 py-1.5
      text-[10px] font-bold uppercase tracking-[0.1em] ${
      phase > i ? 'border-pass/50 bg-pass/10 text-pass'
      : phase === i ? 'border-gilt bg-gilt/[0.12] text-gilt'
      : 'border-border-dark bg-transparent text-muted-ink/60'}`}>
      {phase > i ? <Check className="size-3" /> : <span className="font-mono">{n}</span>}
      {label}
    </div>
  ))}
</div>
```
This is the one place `pass` appears outside a verdict — and it is legitimate: it marks a *phase completed*, not a *judgment validated*. Locating the break at week 19 is objectively correct; committing F6 is not objectively anything.

### 3A — the chart
Sibling file `components/founders/cordell-chart.tsx`. Same geometry constants as `anomaly-chart.tsx` (`W 720 · H 260 · PAD_L 40 / R 20 / T 20 / B 30`), `N = 26`, `BREAK_INDEX = 19`. Single series, weekly active seats.

- Line: `stroke="var(--pass)" strokeWidth={2}` with area `fill="rgba(62,122,95,0.10)"` — a direct visual rhyme with the revenue line at `/`. Someone who played the first track recognises the chart language instantly.
- Grid: `rgba(255,255,255,0.05)` horizontals at 0/25/50/75/100, mono 9px `fill-[var(--muted)]` labels. X ticks every 4 weeks, `W01`-style.
- Solved marker: gilt dashed vertical at index 19 + `r={7}` gilt circle with `stroke="var(--void)" strokeWidth={2}`. Identical to the existing chart.
- Chart panel wraps in the outer panel with three stat tiles above it (`grid grid-cols-2 gap-4 sm:grid-cols-3`, inner-tile classes), showing Cordell ARR `$840k`, share of revenue `20%`, and renewal `Nov 30`. That header rhymes with `stage-data-hunt.tsx` and grounds the chart in stakes.

**Keyboard + touch — mandatory, and the existing chart does not do this.** Each of the 26 hit targets:
```tsx
<circle cx={xAt(i)} cy={yAt(v)} r={14} fill="transparent"
  role="button" tabIndex={solved ? -1 : 0}
  aria-label={`Week ${i + 1}, ${v} active seats`}
  className={solved ? '' : 'cursor-pointer'}
  onClick={() => onPick(i)}
  onKeyDown={(e) => { if (e.key === 'Enter' || e.key === ' ') { e.preventDefault(); onPick(i) } }} />
```
`[tabindex]:focus-visible` in `globals.css` already paints the gilt outline on SVG children — the token exists for exactly this. `r={14}` at 26 points over 720px gives ~26px spacing, so targets are adjacent but not overlapping, and at 375px the rendered radius is ~7px. That is under 44px, which is why the fallback below is not optional:

```tsx
<div className="mt-4 flex flex-wrap items-center gap-2 border-t border-border-dark pt-4">
  <label htmlFor="weekPick" className="text-[11px] text-muted-ink">
    Or select the week the break occurred
  </label>
  <select id="weekPick" ...className="rounded-[var(--radius-sm)] border border-border-dark
    bg-surface px-2 py-2 text-[12px] text-text-warm">
</div>
```
A wrong pick from the `<select>` counts as a `chartMisread` exactly like a wrong click. Same rules, different input device.

Feedback: correct → success toast + phase advance. Wrong → info toast (not error — a misread is exploration, not a violation) and increment `chartMisreads`. *Toast strings for this stage are not in the master spec; I have used the existing sim's register. Orchestrator to confirm or supply.*

### 3B — the evidence terminal
Copy the shell of `diagnostic-terminal.tsx` into the stage file: `overflow-hidden rounded-[var(--radius-md)] border border-border-dark bg-surface`, tab strip `flex border-b border-border-dark`, active tab `bg-carbon text-gilt shadow-[inset_0_-2px_0_var(--gilt)]`, inactive `text-muted-ink hover:text-text-warm`.

Five tabs will not fit at 375px with `flex-1`. Change: `flex overflow-x-auto` with tabs `shrink-0 px-3.5`, icon always visible, label `hidden sm:inline` — same hiding rule the existing terminal already uses.

Per-tab treatment (each earns its own texture; none of them is a card grid):
- **Cordell thread** — three emails stacked with `space-y-3`. Each: inner tile, header line `Dana Whitlock · {date}` in `text-[11px] text-muted-ink`, body `text-[13px] leading-relaxed text-text-warm`. The **third** email gets `border-l-2 border-l-error` and nothing else. One red edge on one email is the entire tonal-escalation device. Do not add a "sentiment: negative" badge.
- **Support tickets** — a mono table. Header row `text-[10px] uppercase tracking-[0.12em] text-muted-ink`, 11 rows `divide-y divide-border-dark py-2.5 font-mono text-[12px]`. The 8 `EVIDENCE_EXPORT_TIMEOUT` rows render that string in `text-error`; the other 3 in `text-muted-ink`. The pattern should be visible as a vertical red stripe before a single row is read.
- **Usage** — a compact restatement, not a second chart: the break week and the release `2.14.0` as two inner tiles.
- **Renata's DMs** — see locked state below.
- **Contract & terms** — key/value rows (`flex justify-between border-b border-border-dark py-3`, label muted, value warm). `NOTICE WINDOW CLOSES TODAY` is the only `text-error font-bold` value on the panel. `No discount request on file` is the fact that kills F6, so give it a `border-l-2 border-l-gilt pl-3` treatment — the one gilt thing in the tab.

**Locked Renata tab.** The tab stays selectable (the copy is the payload) but is marked:
```tsx
{/* tab button when locked */}
<Lock className="size-4" /> ... className="... text-muted-ink/60"
{/* panel */}
<div className="rounded-[var(--radius-sm)] border border-dashed border-border-dark bg-void
                p-8 text-center font-mono text-[13px] leading-relaxed text-muted-ink">
  Renata never got back to you. This source is unavailable.
</div>
```

### ⚠ Spec conflict — read before implementing

```ts

// action === 'ADD_EVIDENCE' in §7's formulas  ->  evidence === true

```
And one open question: should `anselQuestionsInvited` still count C4 when it is `KEEP + evidence`? Design says no — attaching the evidence answers the question before it is asked. Suggested amendment: `(C4.action === 'KEEP' && !C4.evidence ? 1 : 0)`. **Architect decides; I have not assumed it.**

## 6. DENSITY, RHYTHM, AND KNOWING WHERE YOU ARE

### The density curve
The track is 13–16 minutes. Uniform density over eight stages is exhausting; monotonic escalation is worse. The shape is **build → release → peak**:

| Stage | Columns | Live surfaces | Interactive targets | Feel |
|---|---|---|---|---|
| 1 | 1 | 0 | 27 chips + 1 input | Calm. Reading. |
| 2 | 1 + sticky meter | 1 | 48 buttons + 12 selects | First pressure. |
| 3 | 1, three sequential panels | 1 | 26 + 5 + 7 | Investigative. Grows under you. |
| 4 | **2** | 1 (the sheet) | 15 cards | Craft. The page goes quiet and light. |
| 5 | 2 | 2 (readout + pressure) | 8 steppers | Arithmetic under a floor. |
| 6 | **1, narrow** | 1 (trust) | 3 at a time | **Release valve.** Only 3 targets on screen. |
| 7 | 2 | 1 (questions) | 24 chips | Scrutiny. |
| 8 | 1 header + 3 lanes | 3 | 10 cards × 4 chips | **Peak.** Everything at once. |

Stage 6 is the load-bearing part of that curve. It sits between the two most arithmetic-heavy stages and puts exactly three things on screen. Do not enrich it.

### How density escalates without becoming unreadable
Three levers, applied in this order, and never a fourth:
1. **More live surfaces**, not smaller type. Stages 1–3 have one reactive region; Stage 8 has four.
2. **Tighter row rhythm.** Dense lists `py-3.5`; reactive panel rows `py-2.5`. Prose blocks never go below `py-4`.
3. **More columns**, introduced at Stage 4 and never more than two (Stage 8's lanes are a single grid of peers, not nested columns).

**Hard floors that never move, at any stage:**
- Prose: `text-[13px]`, `leading-snug` minimum. Claims and messages go up to 14–15px, never down.
- Labels: `text-[10px]` bold uppercase. Nothing smaller exists in this product.
- Mono numerals: always `tabular-nums`, always ≥11px.
- Touch targets: `min-h-11` below `sm` on every control. No exceptions, including Stage 7's 24 chips.
- Ink on the parchment sheet: never below `text-void/60`.

### How the operator always knows where they are
Four cheap, consistent signals — no progress bars, no percentages:
1. **Sidebar**, `hidden md:flex`, nine rows, done/active/locked exactly as the existing `Sidebar` renders them. It is on screen for the entire desktop run.
2. **`STAGE n / 8`** in every stage header (`hidden sm:block`) and in the mobile brand row (`md:hidden`). One derived string, two places, always agreeing.
3. **The eyebrow** names the *discipline*, not the number — `Stage 5 — Capital Allocation`. Over eight stages the eyebrows read as a curriculum, which is what this product is selling.
4. **Sidebar footer** carries `Est. duration: 13–16 minutes` next to the existing pulsing `bg-pass` dot. A 16-minute session needs to say so up front or it feels like a bug.

*Optional, needs orchestrator sign-off because it is new copy:* a mono clock stamp per stage header (`08:12`, `09:05`, `10:40`, … `18:47`) turning the eight stages into one visible Monday. It is the single cheapest way to make the track feel like a day rather than a quiz. I have not specced it as required because §6.11 makes copy the orchestrator's call.

## 7. CROSS-STAGE CONSISTENCY RULES

The nine rules that make eight independently-written stages read as one product. If an implementer breaks one, it will be visible from across the room.

1. **One header block, duplicated eight times.** `.eyebrow` + `h1 text-3xl font-extrabold tracking-tight text-text-warm` + `p mt-3 max-w-2xl text-[15px] leading-relaxed text-muted-ink`, inside `<section className="stage-enter">`, `mb-6`. Byte-identical structure, three different strings.
2. **One `.eyebrow` per stage.** Every other label in the product is `text-[10px] font-bold uppercase tracking-[0.14em] text-muted-ink`. `.eyebrow` is gilt and has a rule before it; using it twice on a screen destroys the hierarchy it exists to create.
3. **Gilt is intensity; pass/error are verdicts.** §0.3. Four places in the entire track may use pass/error for state: the S2 budget, the S5 board floor, S7's invited questions, S8's budget. Plus S6's trust deltas, which are arithmetic. Nowhere else.
4. **Two panel levels only.** `bg-carbon` outer at `radius-md`, `bg-surface` inner at `radius-sm`. A `bg-surface` panel inside a `bg-surface` panel is a bug.
5. **Lists are `divide-y` rows inside one panel, never N bordered cards.** The only card grids in the track are Stage 3C's facts, Stage 4's options, Stage 6's replies, and Stage 8's items — i.e. only where each item is a *choice*, never where it is a *row*.
6. **One gilt CTA per stage, bottom-left, `w-full sm:w-auto`, revealed with `.reveal-down` when the stage becomes satisfiable.** Stages 5 and 8 are the only exceptions: always present, no reveal, because they have no solved state.
7. **Caps reject, bounds disable.** §0.6. A cap hit produces an error toast + `.flash-error` on the offending row and leaves state untouched. A bound is `disabled` at `opacity-30`.
8. **Numerals never animate.** `tabular-nums` everywhere; containers may `transition-[width]` or `transition-colors`; digits swap instantly. No count-ups, no odometers. This product reports numbers, it does not perform them.
9. **The locked idiom is one thing, used four times** (S3C commit, S4 send, S7 commit, S8 commit): wrapper `pointer-events-none`, unchosen items `opacity-25`, chosen items keep their selected styling and gain a mono `COMMITTED`-class tag. It is the same gesture every time, so the operator learns "this is now behind me" once.

### Spacing scale actually in use
`gap-1.5 / 2 / 2.5 / 3 / 4 / 5` and `p-3.5 / p-5 / p-6 / p-8`, `py-2.5 / py-3 / py-3.5 / py-4 / py-5`, section rhythm `mb-3 / mb-4 / mb-6 / mt-6`. That is the whole scale. It is what the existing four stages already use; do not introduce `gap-7`, `p-4.5`, or arbitrary pixel margins.

### Motion doctrine
Six classes exist. Here is what each is for in this track, and there is nothing else:

| Class | Fires on |
|---|---|
| `.stage-enter` | every `<section>`, once |
| `.reveal-down` | anything that *arrives because you earned it*: CTAs, phase panels, memo paragraphs, pressure lines, footnotes, invited questions, delegate selects, trust deltas |
| `.toast-in` | the shared `ToastStack`, unchanged |
| `.flash-error` | rejections only — never a warning, never a state you can sit in |
| `.blink` | terminal cursors (S3 locked panel, S6 typing, S9 loading) |
| `.pulse` | continuous liveness only (S6 "Marcus is typing", sidebar session dot) |
| `transition-[width]` / `transition-colors` / `transition-all` | meters, bars, selection states, redline restyles |

**Zero new keyframes.** The four I was tempted by and what replaced them:
- *Count-up on the runway number* → replaced by rule 8. The snap is better; it is a model output, not a slot machine.
- *Staggered typing dots in S6* → replaced by `.pulse` on the line + `.blink` on a `_`, which is the product's own terminal idiom and reads more in-world than chat dots.
- *Ink-fill wipe as memo blocks land* → replaced by `.reveal-down` on the paragraph. A wipe would draw attention to the animation; `reveal-down` draws attention to the sentence.
- *Success pulse when the S5 plan clears the floor* → deliberately omitted. This stage has no right answer; congratulating a number would be lying.

Everything above is already covered by the existing `@media (prefers-reduced-motion: reduce)` block, which zeroes both `animation-duration` and `transition-duration` globally. No stage needs its own reduced-motion handling. The only motion-adjacent thing that block does not touch is Stage 6's `setTimeout` pacing, which is correct — it is conversational rhythm, not animation.

### Accessibility contract (per stage, one line each)
| Stage | The thing that would have been skipped |
|---|---|
| 1 | Decorative scrubber is `aria-hidden` and **not** focusable. Chip groups are `role="group"` with `aria-pressed`. |
| 2 | Every delegate `<select>` has a real `<label>` (visually present, not sr-only). Meter is `aria-live="polite"`. |
| 3 | SVG points are `role="button" tabIndex={0}` with `onKeyDown`, **plus** a `<select>` week-picker as an equal-status alternative. Locked tab is reachable and announces its state. |

## 8. WHAT I DELIBERATELY DID NOT ADD

| Not added | Why | The trigger that would justify it |
|---|---|---|
| `<StageHeader>`, `<OptionCard>`, `<Meter>`, `<Chip>` | §6.9. Eight duplications of a 12-line header is a smaller, more readable diff than one component with eight props, and it lets each stage diverge where it should. | A ninth stage, or a **third** track. Two instances is not a pattern. |
| Any new keyframe | Every beat is served. See Motion Doctrine. | A required state change with no visible container to transition — I did not find one. |
| Count-up / odometer numerals | This product reports numbers; performing them undermines the tone. | Never, in this product. |
| Per-stage accent colours | Single-accent discipline is what makes gilt mean something. Eight colours would make it mean nothing. | Never. |
